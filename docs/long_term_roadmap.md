# Long Term Roadmap

## 未来 2 周

目标：

- 把 mock MVP 变成可录屏、可评测、可安全展示的版本。
- 完成真实飞书只读接入前的设计和配置边界。

验收标准：

- README 和 docs 能清楚说明当前是 mock-driven MVP。
- 至少 10 个评测用例草案完成。
- demo 脚本、截图清单和阶段成果材料可直接使用。
- `.env.example` 和权限安全计划完成。

风险：

- 过早接写操作导致安全边界不清。
- 展示文案把计划写成已完成能力。
- 评测仍停留在 smoke tests，不能证明输出质量。

## 未来 1 个月

目标：

- 完成真实飞书文档和会议纪要的只读接入验证。
- 保持 mock fallback 和 dry-run。
- 开始将输出转换为测试群可读的文本消息或卡片草案。

验收标准：

- 至少一个测试文档和一个测试会议纪要可读取并转换为现有结构。
- mock demo 和 tests 不受影响。
- 真实输出不泄露敏感信息。
- 文档说明真实接入状态和限制。

风险：

- `lark-cli` 命令、授权方式或输出格式变化。
- 测试租户权限不足。
- 真实对象字段与 mock 结构差异较大。

## 复赛 Demo 前

目标：

- 固化一条稳定展示链路：读取测试飞书资料 -> 生成会前/会后/对账输出 -> 通过测试群或截图展示。
- 完成阶段成果、项目介绍、Demo 录屏和项目链接。

验收标准：

- Demo 能在本地复现。
- 关键输出有来源。
- 真实接入和 mock 边界讲清楚。
- 无真实密钥和敏感数据进入仓库。

风险：

- 真实 API 或权限在录屏前不稳定。
- 消息分发和写操作的风险高于展示价值。
- OpenClaw 入口接入过早，影响主线稳定性。

## 阶段节奏建议

1. 先把展示材料和评测样例做好。
2. 再接真实只读数据源。
3. 然后接测试群文本消息。
4. 最后考虑卡片、任务、Base 和 OpenClaw。

每一步都保留 mock 回退路径。
