# 场景定义：智能会议纪要 2.0 升级项目

## 场景

团队正在推进“智能会议纪要 2.0 升级项目”。项目涉及产品、研发、测试、运营和项目管理多个角色，信息散落在 PRD、技术方案、上线 SOP、FAQ、测试清单、会议纪要、群聊、任务和推进表中。

MeetingFlow Agent 聚焦会议前后两个高频节点：

- 会前：自动整理会议背景、历史决策、未关闭风险和必读资料。
- 会后：抽取 Action Items，生成任务创建预览，并对重点事项推进表进行对账。

## 目标用户

- 产品负责人：确认范围、风险和上线结论。
- 研发负责人：理解技术风险、监控任务和性能门槛。
- 测试负责人：跟踪回归测试、误召回样本和质量门槛。
- 运营负责人：准备 FAQ、灰度沟通和用户反馈。
- 项目经理：维护推进总表、同步阻塞和跟进行动项。

## 核心痛点

- 会议前上下文分散，参会人需要翻文档、群聊和历史会议纪要。
- 会议后行动项容易停留在纪要中，任务和推进表更新滞后。
- 群聊里存在临时决策和噪声，传统搜索需要知道关键词。
- 文档更新慢于讨论，导致资料和实际结论不一致。

## 为什么普通搜索/问答不够

普通搜索只能返回原始资料，需要用户自己判断哪段重要。普通问答 Bot 往往停在“回答问题”，不会在会前、会后、任务推进这些办公节点主动产出可执行知识。

MeetingFlow Agent 的重点是主动知识服务：会前背景包、会后行动卡片、任务创建预览和推进表对账预览。
