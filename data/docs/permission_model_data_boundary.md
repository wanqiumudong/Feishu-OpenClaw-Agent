# 权限模型与数据边界

## 使用场景

本文件支撑“会前背景包”和“会后行动项同步”两个 demo。Agent 可以读取项目公开 mock 文档、会议纪要、聊天记录、任务表和日历，但不得假设所有内容都对所有人可见。

## 角色权限

| 角色 | 可见范围 | 不可见范围 |
| --- | --- | --- |
| 产品负责人 | PRD、需求评审、客户反馈摘要、上线决策 | 安全测试原始日志 |
| 研发负责人 | 架构、性能、接口契约、技术风险 | 客服原始投诉截图 |
| 测试负责人 | 测试计划、评测样本、缺陷复盘 | 客户个人信息 |
| 安全负责人 | 权限设计、安全评审、审计策略 | 与安全无关的客户运营明细 |
| 项目经理 | 任务、日历、风险、决策摘要 | 需要额外审批的私密会议原文 |

## 数据边界

- `data/docs` 是项目背景与决策材料。
- `data/minutes` 是会议事实源，优先级高于聊天补充。
- `data/chats/project_chat.jsonl` 是状态变化和补充证据来源，不能单独作为最终决策。
- `data/base/priority_board.*` 是待 reconcile 的人为看板，允许存在漏项和不一致。

## 冲突处理

1. 如果 task 状态和 priority board 状态冲突，先输出冲突，不直接覆盖。
2. 如果聊天声明“已完成”但没有文档或会议来源，标记为 evidence_missing。
3. 如果 blocked 项没有 blocker，要求 owner 补齐阻塞原因。
4. 如果日历会议缺少相关文档，背景包中提示“资料不足”。
