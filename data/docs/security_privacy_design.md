# 安全与隐私设计说明

## 原则

智能会议纪要 2.0 的安全边界以“最小可见、来源可追踪、动作先预览”为核心。演示数据全部为 mock，不包含真实 token、真实 user id、真实客户名称或真实企业内容。

## 数据分类

| 类型 | 示例 | 处理规则 |
| --- | --- | --- |
| 公开项目资料 | PRD、测试清单、上线 SOP | 可进入检索上下文 |
| 会议纪要 | 需求评审、技术评审、安全评审 | 仅按会议成员权限读取 |
| 客户反馈 | mock 客户 A/B/C 反馈摘要 | 脱敏后进入 FAQ 和评测样本 |
| 私密字段 | token、cookie、真实 user id | 不进入 mock 数据，也不进入日志 |

## 权限控制

- 外部客户会议默认只输出内部行动项，不把外部发言原文同步到任务标题。
- 跨部门会议摘要需要检查参与人列表，缺少成员时只保留会议级引用。
- 安全评审要求任务同步开关默认关闭，由负责人确认后再进入预览态。

## 日志与审计

- 每次生成结构化结果必须记录 mock source_id。
- 每次建议创建任务必须记录“来源会议 + 证据片段 + 触发规则”。
- 不记录任何 access token、session key、真实 open id 或真实企业 tenant id。

## 未解决问题

- 历史会议的权限变更如何影响已生成摘要，需要在 2.1 版本补方案。
- 客户反馈复盘中出现的截图只保留脱敏描述，不进入当前数据集。
